## 1. Summary of Audit Findings

Every metric in the existing documentation has been evaluated for traceability to raw engine execution log files. The results fall into three categories:
1. **NO SOURCE FOUND**: Hardcoded in python scripts or markdown documents without native C++ engine log files.
2. **SYNTHETIC ONLY**: Derived from synthetic dataset generators (`tools/generate_synthetic_dataset.py`, `tools/generate_field_sample_sweep.py`) using 2D geometric shape drawing (`cv2.ellipse`), incorrectly mislabeled as "Physical Field" or "PSG Tech".
3. **HAND ESTIMATED / PROJECTED**: Manual sums of component timing estimates rather than measured execution logs.

## 3. Contradictions & Discrepancies Flagged

1. **Baseline Latency Contradiction**:
   - `docs/COMPREHENSIVE_BENCHMARK_REPORT.md` Section 3 lists baseline latency as **155.91 ms**.
   - `docs/COMPREHENSIVE_BENCHMARK_REPORT.md` Section 4 (LaTeX table) lists baseline latency as **138.4 ms**.

2. **Full Engine Latency Contradiction**:
   - Section 3 lists optimized engine frame latency as **13.54 ms** (73.9 FPS).
   - Section 4 lists full engine frame latency as **15.3 ms**.
   - `RESEARCH_PAPER_RESULTS.md` Section 5.6 lists full pipeline sweep processing time as **1.54 s** (approx. 25.6 ms/frame over 60 frames).

3. **Embedding Model Name Discrepancy**:
   - `docs/RESEARCH_PAPER_RESULTS.md` Section 5.1 & Appendix B list the embedder as `ArcFace MobileFaceNet` (`arcface_mobilefacenet.onnx`, 13.6 MB).
   - Legacy documentation references `buffalo_s` and `w600k_mbf`.

4. **Terminology Ambiguity ("FAR")**:
   - Previous reports used "FAR" ambiguously for both False Absence Rate (enrolled student marked absent) and False Acceptance Rate (unauthorized guest accepted).
   - **Resolution**: FAR is strictly renamed everywhere into **False Absence Rate (FAbR)** and **False Presence Rate (FPrR)**.

## 4. Root Cause Analysis: Synthetic `PSG_LH0x` Low F1 Score (0.00–0.08)

Debug execution was conducted by running YuNet (`assets/models/yunet_int8.onnx`) directly on frames generated by `tools/generate_field_sample_sweep.py` (`PSG_LH01_FrontRow`):

- **Image outputs saved to**: `docs/benchmark/debug/frame_00_yunet.png` through `frame_04_yunet.png`.
- **Observations**:
  1. **Render**: The generator draws student faces as synthetic 2D color ellipses (`cv2.ellipse`) with simple circles for eyes and lines for nose/mouth.
  2. **Detection**: YuNet (trained on real human face images) misses ~85% of these drawn 2D shape ovals, detecting only 2 to 4 ovals per frame out of 25 ground-truth students.
  3. **Enrollment & Matching**: The few face crops that YuNet detects contain zero actual human biometric facial texture. When ArcFace embeds these crops, it outputs arbitrary noise vectors. Matching these noise vectors against real enrolled student photos yields cosine similarities well below `tau_match` (or near random), resulting in near-zero recall and $F_1 \approx 0.0556$.
